# CHAPTER 9 — MAINTENANCE OF THE SYSTEM

## 9.1 Corrective Maintenance
In DiagnoLabs, our main priority for corrective maintenance is identifying and fixing bugs as quickly as possible. During development, we used standard console logging, but for production, we rely on Winston for structured error logging. We built an Express error-handling middleware that catches synchronous errors, and we explicitly handle unhandled promise rejections and uncaught exceptions to prevent the Node.js 20 LTS server from crashing silently. When a bug is reported by a user (e.g., a Phlebotomist unable to scan a QR code), the Support Staff logs the issue. G. Avinash (DevOps & QA) tracks these logs to pinpoint where the frontend or backend failed, allowing G. Siva Manikanta and D. Venkat Sai to issue a patch. 

## 9.2 Adaptive Maintenance and Cloud Scaling
As the platform grows, we have to ensure it handles more traffic. The system adapts to increased load using several cloud-native features. Our Node.js backend is hosted on Render, which supports auto-scaling based on CPU and memory usage. For our database, we use MongoDB Atlas; we started on the free M0 cluster but can scale to an M10 or higher tier as storage and IOPS requirements increase. The frontend, built with React 18 and Vite 5, is deployed on Vercel. Vercel automatically utilizes edge caching and a global CDN for our static assets (HTML, CSS, JS, and images). To prevent database connection limits from crashing the server during peak hours, we implemented database connection pooling using Mongoose.

## 9.3 Preventive Maintenance and Database Backup Strategy
To avoid data loss, especially critical Patient reports, we rely on MongoDB Atlas automated backups. The cluster takes snapshots every 6 hours and supports point-in-time recovery (PITR). We also set up daily API health check scripts that ping our core endpoints (e.g., the JWT login route and the patient dashboard route) to ensure the server is responsive. G. Siva Manikanta runs `npm audit` weekly to check for vulnerabilities in our dependencies, like bcryptjs or Express, updating them when security patches are released. We don't have to worry much about SSL certificate renewals since Vercel and Render handle TLS automatically for their subdomains, but we monitor expiry dates just in case.
