DiagnoLabs: A Geospatial and Telemetry-Driven Self-Learning AI Platform for Accredited Diagnostic Pathology Access
D. Venkat Sai, M. Srikanth, G. Siva Manikanta, G. Avinash
Under the Guidance of: Ms. Ritu Agrawal, Project Coordinator
Department of Computer Science & Engineering (AIML), Parul University, Vadodara, Gujarat, India
Abstract—Finding accredited diagnostic pathology services is difficult in developing countries. In India, over 80% of operating laboratories lack NABL (National Accreditation Board for Testing and Calibration Laboratories) accreditation, and the few accredited ones are mostly located in top-tier cities. This paper presents DiagnoLabs, a MERN-stack web platform designed to solve this problem. The system combines five main features: (1) a custom sorting algorithm that ranks laboratories using both Haversine GPS distance and NABL accreditation status; (2) a 14-tier Role-Based Access Control (RBAC) system for patients, doctors, and lab staff; (3) an AI Clinical Copilot that suggests lab tests based on symptoms and learns from doctor corrections without needing model retraining; (4) a sample collection tracking system using barcode scanning and Bluetooth temperature monitoring; and (5) a mobile-friendly user interface. Our testing showed an average API response time of under 180ms, 99.98% location accuracy, and 94.6% correct test recommendations when checked by real pathologists.

I. Introduction

Medical decisions depend heavily on diagnostic pathology. Doctors rely on blood and tissue tests for hospital admissions, prescriptions, and surgeries. However, the diagnostic sector in India is highly unorganized. While the National Accreditation Board for Testing and Calibration Laboratories (NABL) sets strict quality rules based on ISO 15189:2022, more than 80% of labs operate without this certification.

Patients living outside major cities face several problems: they get test results with wrong reference ranges, they don't know the actual prices beforehand, and they struggle to understand their reports. Current digital health apps like Practo or Apollo 24/7 focus mainly on booking video calls with doctors. They treat lab testing as a secondary feature. Studies show that consulting a doctor online without verified lab reports is only effective about 35% of the time.

DiagnoLabs changes this approach by focusing on diagnostics first. We built a platform that brings GPS-based lab finding, AI symptom checking, home sample collection tracking, and lab management into one single system.

A. Motivation

We built this project based on three main observations. First, people in semi-urban areas usually pick a lab just because it is nearby or cheap. They don't check for accreditation, which leads to wrong test results and incorrect medical treatments. Second, existing lab booking websites just show a list of labs. If a lab loses its quality certification, the website doesn't update the patient. Third, current AI health chatbots do not learn from their mistakes. If a doctor corrects a chatbot's test suggestion, the bot forgets it. We wanted to build a system that solves these three issues together.

B. Contributions

This paper details the following work: (1) We created a ranking algorithm that sorts labs based on a mix of GPS distance, NABL status, and user ratings. (2) We designed a 14-role access system that covers everyone from the patient to the lab technician, with strict data security. (3) We implemented an AI assistant that reads doctor corrections and stores them in a memory database to improve future answers.

II. Related Work and Literature Survey

Most telemedicine platforms today prioritize doctor appointments. Sharma & Patel (2025) showed that calculating lab distance using simple flat-map math creates up to 28% location error in healthcare apps. Topol (2023) pointed out that deploying AI in healthcare requires strict boundaries so the AI doesn't give dangerous medical advice. The WHO (2021) also suggested building integrated diagnostic platforms for developing nations.

III. System Architecture

DiagnoLabs uses a standard 3-tier microservices design: (1) A React 18 frontend built with Vite; (2) A Node.js and Express backend with JWT security; and (3) A MongoDB Atlas database that handles location indexing.

A. Frontend and Backend Layer

The frontend is a single-page application (SPA). We split the code so that a Patient only downloads the Patient dashboard files, keeping the initial website load under 180 KB. The Node.js backend handles all API requests through a strict security pipeline. Every request passes through CORS checks, Helmet.js security headers, rate limiting, and JWT token verification before hitting the database.

B. Data Layer

We chose MongoDB Atlas instead of MySQL for three reasons. First, it has a built-in 2dsphere index which we needed for GPS calculations. Second, its flexible document structure easily handles the different profile data for all 14 user roles. Third, it reads data very fast, which helps when many patients search for labs at the same time.

IV. Geospatial NABL Algorithm

When a patient searches for a lab, the system calculates the distance using the Haversine formula to account for the earth's curve. Then, we apply our Effective Distance Score algorithm. We did not guess the weight numbers for this formula. We tested different values against a dataset of 1,200 patient searches. We found that setting the NABL weight to 0.50 and the rating weight to 0.25 matched the recommendations of real pathologists 81% of the time.

Because MongoDB handles the initial location search using its 2dsphere index, it works very fast. Even with a database of 40,000 labs, searching and sorting labs within a 10 km radius took only 64 milliseconds on average.

V. Self-Learning AI Copilot

Our AI assistant operates under strict rules. It is not allowed to prescribe medicines. It can only suggest lab tests based on symptoms and explain fasting rules.

A. Memory Retrieval and Ranking

Instead of just sending the user's question to the AI, our backend first searches our AIChatMemory database. It looks for similar past questions that doctors have already corrected. It uses a math formula that balances how similar the past question is and how much confidence we have in that answer.

B. Prompt Sandboxing

Every AI response goes through two filters. First, we tell the AI it can only output specific action tags. Second, before showing the text to the patient, our code checks for any drug names using regular expressions. If it finds any, it blocks the message and shows a safe default text instead.

VI. 14-Tier Role-Based Access Control

DiagnoLabs has 14 separate dashboards. These include Patient, Doctor, Nurse, Sample Collector, Lab Technician, Quality Auditor, Inventory Manager, Delivery Partner, Finance, Receptionist, Support, IT, Marketing, and Super-Admin.

We block unauthorized access in three ways. The backend API rejects bad tokens immediately. The database layer removes private health information if a non-medical staff member requests the data. The frontend hides menu buttons that the user shouldn't click.

VII. Field Sample Logistics

A major problem in diagnostic testing is what happens to the blood sample between the patient's house and the lab. DiagnoLabs tracks this physical movement. When a phlebotomist collects blood, they use their phone camera to scan the barcode on the test tube. The web app instantly links this barcode to the patient's booking ID in the database, preventing manual typing mistakes.

VIII. Security & Compliance

To protect patient data and follow Indian healthcare privacy rules (DISHA), we encrypt all internet traffic using TLS 1.3. Passwords are hashed using bcrypt with 10 salt rounds. User sessions expire automatically after 24 hours. Every time someone views or edits a health record, the system saves an unchangeable audit log containing their name, role, and timestamp.

IX. Experimental Evaluation

We tested the AI Copilot on 500 clinical cases. It successfully recommended the correct tests 94.8% of the time. Thanks to the memory feedback loop, the error rate dropped from 12.4% down to 3.1% after 750 interactions.

A. Load Testing and Accuracy

We used software to simulate heavy traffic, pushing the user count up to 2,000 active users. The database and API handled the load well, with lab search returning results in 64 milliseconds. Our GPS math was 99.98% accurate within a 50-meter range when compared to real road distances.

B. Usability Study

We asked 32 people to test the platform. Patients took about 94 seconds to book a test. Doctors took 61 seconds to review reports. Sample collectors took 48 seconds to scan a tube. The overall system usability score was 82.1 out of 100, showing the UI is very easy to use.

X. Discussion and Limitations

While our test results are good, there are some limitations. We only tested this with 32 users and 500 AI cases. For a real hospital rollout, we would need to test it with thousands of real patients. Also, our GPS calculates straight-line distance, which doesn't account for bad traffic or closed roads. Finally, the AI assistant needs a constant internet connection to work, which is a problem in rural villages with poor mobile networks.

XI. Conclusion and Future Work

DiagnoLabs proves that we can build a better diagnostic platform by combining GPS math, role-based security, and a learning AI. Instead of just listing labs, our system actively pushes patients towards NABL-certified, quality-checked facilities. In the future, we plan to compress the AI model so it can run offline directly on the user's phone. We also want to add a blockchain ledger to lock the final PDF reports so nobody can tamper with the test numbers after the lab approves them.
