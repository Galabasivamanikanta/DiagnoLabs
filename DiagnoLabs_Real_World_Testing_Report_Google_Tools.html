2. Objective

The objective of testing is to verify that the DiagnoLabs application functions according to the specified requirements, adheres to rigorous clinical diagnostic standards (NABL ISO 15189:2022 and ICMR testing protocols), meets high-availability performance criteria under heavy load, protects sensitive Electronic Health Records (EHR) through OWASP-compliant security controls, and identifies defects before deployment.

3. Testing Scope

The testing scope encompasses complete verification across six primary vectors:

  • Functional Testing: End-to-end verification of 14-role authentication, booking lifecycle, automated OTP phlebotomy sample verification, report generation, and billing invoices.
  • UI Testing: Mobile-responsive viewport testing (320px to 4K), cross-browser rendering, touch target sizing, and accessibility standards compliance (WCAG 2.1 AA).
  • Integration Testing: Validation of Google Identity Services (GIS OAuth 2.0), Leaflet geospatial mapping, and Google Gemini AI Clinical Assist fallback mechanisms.
  • Performance Testing: High-concurrency load stress testing up to 5,000 virtual users (VUs), server response latency, memory leak profiling, and Google Lighthouse core web vitals.
  • Security Testing: OWASP Top 10 penetration testing including NoSQL injection, Broken Object-Level Authorization (BOLA/IDOR), CSRF protection, and JWT integrity.
  • Compatibility Testing: Cross-platform evaluation across Windows 11, macOS Sequoia, Android 14, iOS 17, Google Chrome, Mozilla Firefox, Microsoft Edge, and Safari.
